= Operations

The server binary runs as `server [--config <file>] [--role=all|web|worker]` and the admin
tool as `cli [--config <file>] <command>`; both read the same configuration (file plus
`APP__*` environment variables, see xref:configuration.adoc[configuration reference]).

== Roles

[cols="1,3"]
|===
|`--role=all` |Default. Web (pages, REST API, SSE, `/assets`) and worker in one process.
|`--role=web` |HTTP only. Events from workers arrive over Postgres `LISTEN/NOTIFY`.
|`--role=worker` |Job queue (catalog refresh, image fetch, eviction, cron) and the search
indexer. Run as many as you like; jobs are claimed with `FOR UPDATE SKIP LOCKED`.
|===

Every process applies pending database migrations at start-up (`cli migrate` does the same
on demand).

== Backup

Postgres is the source of truth. Back up:

* the Postgres database (`pg_dump -Fc`), which includes the job queue, the outbox, the
  storage index and all user data;
* user uploads in the blob store: objects under `up/` (fs backend: `<fs_root>/up/`). Image
  variants (`img/`) and cached provider responses (`http/`) are derived data and are
  regenerated on demand after a restore;
* the brand directory if you changed it.

Meilisearch does not need a backup: after a restore run `cli reindex --clear`.

== Search index

[source,shell]
----
cli reindex           # queue every catalog item, library entry and companion
cli reindex --clear   # empty the indexes first (removes documents of deleted rows)
----

The worker's indexer processes queued rows in batches of 200. If Meilisearch is unreachable
when a process starts, that process uses the Postgres fallback search (logged as an error);
restart it once Meilisearch is back.

The server talks to Meilisearch with the master key only at start-up, to configure the
indexes and to create (or reuse) a key limited to this deployment's indexes
(`search.index_prefix`) and to search and document actions. Browsers never receive any
Meilisearch key; every query goes through the server, which adds the owner filter for
per-user indexes.

== Storage report

[source,shell]
----
cli storage report --dry-run   # usage, limits, S3 counters, what eviction would remove
cli storage report --json
cli storage evict              # evict now instead of waiting for the background job
----

The report also shows the Postgres database size and, with the Meilisearch backend, its
document count and database size. Both are reported, not budgeted. See
xref:storage-budget.adoc[storage budget].

== API

The REST API is described by an OpenAPI document at `/api/v1/openapi.json` (titled with the
product name). Sign in with `POST /api/v1/auth/sign-in` and send the returned token as
`Authorization: Bearer <token>`. Browsers use the session cookie instead; state-changing
requests from other sites are refused (checked with `Origin` and `Sec-Fetch-Site`).
Sign-in is throttled after 10 failed attempts for a name within 15 minutes. JSON request
bodies are limited to 2 MiB, import uploads to 64 MiB.
