= White-labelling

No product name, logo, colour, domain or support URL is hard-coded. Everything brand
specific comes from a brand directory; a test fails if the codename appears in code outside
`config/brand/` and `docs/`.

== Brand directory

Point `APP__BRAND__DIR` (or `brand.dir` in the config file) at a directory containing a
`brand.toml`:

[source,toml]
----
name = "Reading Room"          # product name: page titles, header, OpenAPI title, TOTP issuer
short_name = "Reading Room"    # cookie names and the outgoing User-Agent use its ASCII letters
default_locale = "de"          # used when the browser's Accept-Language matches no locale
support_url = "https://example.org/support"   # added to the User-Agent

[legal]                        # footer links on the sign-in and sign-up pages; labels from the
                               # `legal-<key>` messages (imprint, privacy, terms), else the key
imprint = "https://example.org/imprint"
privacy = "https://example.org/privacy"

[theme]                        # CSS custom properties for the light theme
primary = "oklch(0.55 0.2 145)"
primary-foreground = "oklch(0.98 0 0)"

[theme_dark]                   # the same for the dark theme
primary = "oklch(0.7 0.18 145)"

[logos]                        # files inside the brand directory (read, not displayed yet)
light = "logo-light.svg"
dark = "logo-dark.svg"
favicon = "favicon.svg"

[strings.de]                   # override any message key, per locale
nav-library = "Regal"

[fonts]                        # optional UI font, self-hosted from the brand directory
sans = "Inter"                 # family name, put in front of the system stack

[[fonts.files]]                # WOFF2 only; weight is one value or a variable range
file = "fonts/Inter.woff2"
weight = "100 900"
style = "normal"               # normal or italic
----

Nothing else changes: the same binary renders another brand (`apps/server/tests/it/brand.rs`
checks product name, theme tokens, locale, string overrides and cookie names).

== What is derived from the brand

[cols="1,2"]
|===
|Session cookie |`<ident>_session`, where `<ident>` is `short_name` reduced to lowercase ASCII
letters and digits
|OIDC state cookie |`<ident>_oidc`
|Outgoing `User-Agent` |`<ident>/<version> (+<support_url>)`
|OpenAPI title |`<name> API`
|TOTP issuer |`name`
|Theme |`[theme]` and `[theme_dark]` become `:root:not(.dark){...}` and `:root.dark{...}`, which
outrank the stylesheet defaults; a theme without values keeps the defaults; values that could
break out of the style element are dropped. At start-up the server logs a warning when
`primary` on `primary-foreground` is below 4.5:1 (WCAG 1.4.3) or cannot be checked (use hex,
`rgb()` or `oklch()`)
|Font |`[fonts]` becomes `@font-face` rules (`font-display: swap`) with URLs below
`/brand/fonts/<fingerprint>/` on the same origin (cached as immutable) and `--font-sans`
= the brand font, then the system stack. Files must exist and be WOFF2, or start-up fails.
Ship the font licence (for example `OFL.txt`) in the brand directory. The default brand ships
Atkinson Hyperlegible Next (OFL 1.1, see `config/brand/ICONS.adoc`)
|Messages |`[strings.<locale>]` wins over the built-in Fluent messages
|===

== Messages and locales

Built-in messages live in `src/rust/crates/web/locales/<locale>.ftl` (pages) and
`src/rust/crates/notify/locales/<locale>.ftl` (notifications and emails), both Fluent; locales
`en` and `de`. Overrides in `[strings.<locale>]` are Fluent too: they may use variables,
plurals (`{ $count -> [one] ... *[other] ... }`) and `NUMBER()`.

The repository test `xtask/tests/locales.rs` fails when a key exists in one locale only, a
message uses other variables than its English original, a value is empty, code uses a key
that does not exist or a key is no longer used, `view!` markup has hard-coded text, or a
brand override names an unknown key.

The locale is chosen in this order (DEC-201): the signed-in user's language (account menu or
the You page; stored per account), the browser's `Accept-Language`, the brand's
`default_locale`. Notifications and emails use the recipient's language, else
`default_locale`. Numbers and dates follow the locale (`3,5` and `06.11.2026` in German);
times are shown in UTC (DEC-200).

== Feature toggles per deployment

* `features.kinds`: enabled media kinds (empty = all).
* `connectors.<id>.enabled`: turn a data source off.
* `auth.signup`: `open`, `invite` or `closed`.

== Logos of other services

Operators may hide integrations and data sources, but must not use third-party service logos
as their own branding. A licence notices page is planned; until then, vendored icon files and their licences are
listed in `config/brand/ICONS.adoc`.

== Data source terms

Some providers restrict commercial use (for example TMDB requires a commercial agreement for
paid services). An operator who rebrands and sells this application is responsible for the
providers' terms, see xref:connectors.adoc[connectors].
