= Integrations

Other systems can tell the server what you watched: a media server, a home automation
system, or your own script. They post one JSON document per finished movie or episode to
the *watched webhook*; the play is recorded in your history, the item is added to your
library (and filled in from the metadata sources in the background), and your open pages
update right away.

== Tokens

Create a token per sender under _Integrations_ in the web app (or
`POST /api/v1/integrations` with `{"name": "Jellyfin"}`). The answer contains the webhook
URL and the token; the token is shown once (only a hash is stored). Revoking the integration
stops the token. The page shows when each sender last called and whether that call was
refused, with the reason.

== The webhook

`POST <public URL>/api/v1/hooks/watched` with `Authorization: Bearer <token>` and a JSON
body:

[cols="1,1,3"]
|===
|Field |Type |Meaning

|`kind` |`movie` or `episode` |required
|`title` |string |movie title (for episodes: the episode title, informational)
|`year` |number |release year, optional
|`ids` |object |provider ids of the movie, e.g. `{"tmdb": "949", "imdb": "tt0113277"}`
|`series` |object |episodes: `{"title", "year", "ids"}` of the series
|`season`, `episode` |numbers |episodes: required
|`watched_at` |RFC 3339 time |default: when the webhook arrives
|`source` |string |shown in the notification, e.g. `Jellyfin`
|`id` |string |the sender's id for this play, optional: posts with the same id are one play
|===

At least one provider id (`tmdb`, `imdb`, `tvdb`, ...) is required; it decides which item is
meant. Unknown fields are refused, so typos in a template show up as errors instead of being
ignored. Posting the same play again (same item and episode, and the same `id`, else the same
`watched_at`, else within the same 15 minutes) records it once.

Answers: `200` with `{"item_id", "event_id"}`, `401` for an unknown or revoked token, `422`
with a message for an invalid body.

[source,shell]
----
curl -X POST https://tracker.example.org/api/v1/hooks/watched \
  -H 'Authorization: Bearer itk_...' -H 'Content-Type: application/json' \
  -d '{"kind": "episode", "title": "Good News About Hell",
       "series": {"title": "Severance", "ids": {"tmdb": "95396"}},
       "season": 1, "episode": 1, "source": "Jellyfin"}'
----

== Jellyfin

Jellyfin's webhook plugin can send a JSON body built from a template you write. Point it at
the webhook URL, add the header `Authorization: Bearer <token>`, send it on playback stop
(or when an item is marked played), and write the template so that it produces the document
above, filling the fields from the plugin's template variables (see the plugin's own
documentation for their names).

This project does not ship a Jellyfin-specific adapter or polling: Jellyfin and its plugin are
GPL-licensed, and this MIT project does not use their code or documentation (DEC-149).
