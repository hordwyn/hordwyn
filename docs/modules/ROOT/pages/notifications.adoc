= Notifications

Every notification lands in the user's *inbox* (web app: _Notifications_). Subscriptions send
copies to *channels*: email, ntfy, Gotify, Discord, Matrix, the Apprise API and signed
webhooks (browser push follows later).

== Events

Each event has a stable id (`GET /api/v1/notifications/events`). Subscriptions match an id,
a group (`social.*`) or everything (`*`), optionally filtered by kind, list, item or
companion.

[cols="1,2"]
|===
|Group |Events

|`release` |item released, new episode, new chapter, release date changed
|`library` |status changed in a list, metadata changed
|`social` |link request, link accepted, session shared with you, list shared
|`boardgame` |loan due, loan overdue, wishlist game owned by a linked user
|`integration` |play recorded, integration failing
|`import` |import finished, import failed
|`admin` (admins only) |storage almost full, storage full, connector unavailable, new account, job backlog
|===

The same event about the same thing (for example the same episode) reaches a user once.

Emitted today: `social.link_request`, `social.link_accepted`, `social.session_shared`,
`import.finished`, `import.failed`, `integration.play_recorded`, `admin.signup`,
`admin.storage_high` and `admin.storage_full`. The other events are in the catalogue (you
can subscribe to them) but nothing sends them yet (DEC-143).

== Delivery

`immediate`:: sent right away, or when the subscription's quiet hours end (local time in the
  subscription's timezone).
`digest`:: collected and sent together on a cron schedule in the subscription's timezone,
  e.g. `0 8 * * *` for every morning at eight.

A rate limit (deliveries per channel and event per hour) suppresses the excess; suppressed
notifications stay in the inbox. Failed sends are retried with backoff
(`notify.max_attempts`); a target that answers _gone_ (HTTP 410, expired push subscription)
disables the channel. The delivery log (`GET /api/v1/notifications/deliveries`) shows each
attempt's state and error.

Admins can set instance defaults (`PUT /api/v1/notifications/subscriptions` with
`"instance_default": true`) and lock them so users cannot mute them.

== Channels

[cols="1,3"]
|===
|Kind |Settings

|`email` |`to`; the server needs `notify.smtp`
|`ntfy` |`server`, `topic`, optional access `token`
|`gotify` |`server`, application `token`
|`discord` |`webhook_url`
|`matrix` |`homeserver`, `room_id`, `access_token` (the account must be in the room)
|`apprise` |`server` of an Apprise API instance, `urls` (Apprise URLs)
|`webhook` |`url`, `secret` (empty: generated and shown once)
|`web_push` |not available yet (DEC-141)
|===

Tokens and secrets are never shown again after saving. Targets in private networks
(`192.168.x.x`, `localhost`, ...) are refused unless the operator sets
`notify.allow_private_targets = true`, or allows single hosts in
`outbound.allow_private_hosts` (for example `["ntfy.lan:8080"]`); the first setting also
decides whether sign-in providers and the mail server may be there
(xref:operations.adoc[Operations, "What the server connects to"]).

=== Verifying webhooks

Webhooks follow the https://www.standardwebhooks.com/[Standard Webhooks] scheme. Each
request carries `webhook-id`, `webhook-timestamp` (Unix seconds) and
`webhook-signature: v1,<signature>`, where the signature is the base64 HMAC-SHA256 of
`<id>.<timestamp>.<raw body>` with the base64-decoded part of the `whsec_` secret as key.
Reject requests whose timestamp is too old, and use `webhook-id` to ignore retries you have
already handled. The body is
`{"type": "<event id>", "timestamp": "...", "data": {"title", "body", "link"}}`.

== Texts

Texts are per event (and optionally per channel kind) in the instance language. The brand can
override them in `brand.toml` (`[strings.en]`, keys like `release-episode-title`), admins at
runtime (`PUT /api/v1/notifications/templates`). Arguments are written `{ $title }`;
`{ $product }` is the product name.
