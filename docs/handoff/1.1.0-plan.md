# Plan: release 1.1.0

Written 2026-11-20 after release 1.0.1, from the owner's cut of milestone 1.1.0 (DEC-866).
1.1.0 is a minor release: additive migrations are allowed (0002 and up; the baseline 0001
stays frozen), no breaking change of the REST API, the export format or settings.

## Scope (GitLab milestone 1.1.0)

| Package | Issues | Migration |
|---|---|---|
| A. Book editions | #20 editions on the library entry (owner reads a book that needs it now) | yes: the edition of an entry |
| B. Episodes and counts | #10 episode names (priority), #11 how often each item and episode was consumed, #14 repeat count settable by hand, for every kind | yes: episode titles; earlier unlogged passes on the entry |
| C. Sharing | #35 Copy to my log feedback, #13 "Watched with" after the fact, #15 linking both ways, #19 automatic, configurable sharing with linked people (priority) | likely: a sharing setting per link; progress on a session for #19 |
| D. Small | #16 override year and title, #18 version and About page | no |
| E. Design only | #34 task executor in the admin panel | none (a design agreed with the owner, built in a later minor) |

Moved out on 2026-11-20: #12 (find a show by season name or alternative title; needs a
brainstorm) and #17 (instance language in Admin) to `Later 1.x`.

## Order

1. **A** first: the owner needs editions for a book started on 2026-11-20 (meanwhile: set the
   page total of the edition by hand, "Change" on the book's page; it is kept as `user`).
2. **B**: the owner's top item (#10), with #11 and #14 on the same data.
3. **C**: #35 is a small fix; #19 needs a short design with the owner first (what a linked
   person gets automatically, per link or per person, shows and books with their progress).
4. **D**, any time between packages.
5. **E**: the design of #34 is written beside the packages and walked through with the owner.

## How each package is run

As in `docs/handoff/1.0.1-go.md` (rules binding): a branch per package, a test that fails
before each fix or feature, decisions recorded (next free DEC after DEC-866), CHANGELOG under
`[Unreleased]`, every new migration with `UPDATE_SCHEMA=1`, the upgrade seed regenerated and
`upgrade-test` green from v1.0.1, full gate locally and on GitLab, merge without squash. Owner
questions with a recommended option. The release itself follows HANDOFF section 1 (release
candidate on staging first).
