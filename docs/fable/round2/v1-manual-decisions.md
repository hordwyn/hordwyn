LC-23 | v1-manual B2: `App::detail` must not queue a refresh "when no registered source could answer", but the `app` crate does not know the sources (architecture rule D-3). Who decides, and what counts as "could answer"? | One rule, `catalog_core::refresh::source_known(registry, item)`: a registered connector that gives details for the item's kind and in whose namespace the item holds an external id; the key and the Disabled switch of the connector do not matter. The API hands it to `App::item_detail_where(id, watcher, answerable)`; `App::item_detail` and `item_detail_for` (callers without the sources: tests, small setups) ask for any external id. The refresh job uses the same rule and leaves such an item untouched (before: marked failed, retried every hour). The watched webhook queues a refresh only for an item with an external id.
