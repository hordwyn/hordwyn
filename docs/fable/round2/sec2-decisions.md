# sec2 decisions (lane A2; the orchestrator renumbers them into docs/DECISIONS.md)

Format: `LA-n | question | choice | alternatives | how to reverse | source`

LA-1 | What does the progressive delay of DEC-535 count, so that nobody can keep an account shut by guessing? | The count belongs to the pair of account name and client address (`crates/auth/src/throttle.rs`): the first `auth.throttle.free_failures` (3) failures of a pair cost nothing, the next one a wait of `delay_base_secs` (1 s), doubling with each further failure up to `delay_max_secs` (300 s); during a wait the pair is answered `429` with `Retry-After` and nothing is verified; a success clears the pair; a pair without a failure for `window_minutes` (15) starts again. Guesses at `admin` from one address therefore never make the owner wait at another address (the test "the admin name cannot be locked by guesses from another address"). A wait per account alone would be a lock in effect: whoever guesses again the moment a wait ends keeps the account waiting. Known and accepted: guesses at one account spread over many addresses are bounded per address only (pair delay and address budget), not per account; what bounds them is the password length rule (10 characters), TOTP where enrolled (whose wrong codes are counted per account alone, LA-12), and the verification cap. Unknown names are counted like known ones, so the wait reveals nothing | a wait per account across all addresses (a lock for the owner under a steady attack); a hold inside the request instead of a refusal (ties up connections, needs a queue per account) | key the pair without the address in `Throttle::begin` | DEC-535; security-audit.md SEC-5; next-packages.md sec2 tests

LA-2 | The budget of a client address | `auth.throttle.address_failures` (30) failures across all names per window of `window_minutes` (15), a fixed window that starts with the first failure; over budget, every check from the address is refused (`429`, `Retry-After` until the window ends) for every name. Attempts being checked count against the budget, so a burst of parallel requests cannot run ahead of its own failures or fill the queue of the verification cap. A success does not refill the budget (one known account would otherwise pay for guesses at others). IPv6 addresses are counted per /64 network, IPv4 per address. The address is the one `server.trusted_proxies` yields (DEC-284); callers without an address (the command line) are slowed per account only. Behind a proxy that is not listed in `server.trusted_proxies` every visitor has the proxy's address and shares one budget: the reverse-proxy page says so, and the server logs one warning when a request with `X-Forwarded-For` arrives from a peer that is not trusted | no budget in flight (a burst of thousands of parallel guesses would all be verified); a sliding window (more state per address for little gain) | `Throttle::begin` | DEC-535; security-audit.md SEC-5 scenarios b and c

LA-3 | Where the throttle applies | Every check of a secret: sign-in and the local sign-in (password, TOTP, recovery code), "Is this your account?" with a password, re-authentication, the current password of a password change, the code that confirms an authenticator, reset links (no account is known: the address budget only) and emailed sign-in links (pair of the ticket's account and the address). One count per pair for all of them. The client address reaches `auth` through a task-local set by the request layer (`auth::client::scope` in `api::request_meta::layer`), not through a parameter of each of the roughly sixty call sites | an address parameter on every checking function | pass the address explicitly and drop `auth::client` | security-audit.md SEC-5; task brief

LA-4 | Counters: where | Behind `auth::AttemptCounters` with the in-memory `MemCounters` (at most 20 000 keys, stalest first out). No Postgres store and no migration: one web process is the supported shape (HANDOFF 4.8, v1-plan addendum 2026-11-12), so the separable last step of DEC-535 is not built | the Postgres store now | implement `AttemptCounters` over a table and hand it to `Auth::with_counters` | DEC-535; HANDOFF 4.8

LA-5 | The cap on concurrent password verifications | `auth.throttle.verify_concurrency` (8) argon2 verifications at once per process, a semaphore around every verification (passwords and recovery codes); the next ones wait their turn. Hashing a new password (sign-up, change, reset) is not capped: it runs only after an invite, a session or a reset link was accepted. The value is read at start; the other throttle values too (file and environment only, not in the admin UI) | cap hashing too; refuse instead of queueing | `VerifyGate` in `throttle.rs` | security-audit.md SEC-5 fix (8)

LA-6 | Redirects on the governed HTTP client (DEC-534 "no redirects, or the allowlist re-checked per hop") | Re-checked per hop: the client itself follows nothing (`redirect(Policy::none())`); `GovernedHttp::send` follows a redirect of a `GET` or `HEAD` at most 5 times, each hop only to a host on the connector's list, never from https to http, and with the private-address rule applied again; other methods get the redirect back as the answer. The caller's headers (API keys) and the cache validators go only to the origin the request was made for (reqwest's own redirect handling forwarded a custom key header to the other host: seen in the red run of `a_redirect_to_an_allowed_host_is_followed_without_the_callers_headers`). A refused hop is `HttpError::Blocked`, is not retried and does not count for the circuit breaker. No redirects at all was not taken: Open Library answers `/isbn/{isbn}.json` and every cover with a redirect (docs/connectors/openlibrary.md) | `Policy::none()` and nothing else; reqwest's `Policy::custom` (it does not know the connector of a request) | `GovernedHttp::send` | security-audit.md SEC-4; DEC-534; v1-plan.md 3.5

LA-7 | Host list entries for hosts whose names change (Open Library covers redirect to numbered `ia*.us.archive.org` hosts; v1-plan B9) | A list entry with a leading dot, `.archive.org`, covers the domain and all of its subdomains on the default port; `host` and `host:port` entries are exact as before. The Open Library connector (package v1-books, another lane) has to list `.archive.org`; written into docs/connectors/openlibrary.md and the connectors page. No connector on this branch uses a suffix entry | a wildcard syntax (`*.archive.org`); listing the numbered hosts (their numbers vary per item) | `host_matches` in `crates/catalog-core/src/http.rs` | docs/connectors/openlibrary.md Hosts row; v1-plan.md B9

LA-8 | Private addresses on the governed client ("no requests to private ranges unless an admin allowlists a host") | Two reqwest clients inside `GovernedHttp`: one resolves names through `PublicOnly` (a name with one private address among its answers is refused at connect time, so DNS cannot change between check and request), one resolves normally. A request uses the second only when the connector's `PrivateRule` allows it or its host is on the operator's list (`GovernedHttp::with_private_hosts`); an IP literal in a private range is refused before any connection. Data sources: `PrivateRule::Blocked`. The operator's list is `outbound.allow_private_hosts` (new setting, file and environment only, `host` or `host:port`) plus the host of every `connectors.<id>.base_url`: only the operator can set a base URL and it names the host on purpose, so a mirror on the LAN and the test servers on 127.0.0.1 need no second setting. Not in the admin UI: an admin of a hosted instance must not be able to open the operator's network | block connector base URLs on private addresses too unless listed twice; an allowlist editable in the admin area | `private_hosts` in `apps/server/src/lib.rs` | task brief; DEC-534; security-audit.md SEC-4

LA-9 | `notify.allow_private_targets` as "the explicit override in both directions" (DEC-534) | The setting becomes optional (was a boolean, default false). Not set: notification channels are refused on private addresses as before; sign-in providers and the mail server follow `instance.hosting` as it is at the time of the request (home: allowed, hosted: refused; the admin can change the mode at run time). `true` allows all three, `false` refuses all three, in either mode. OIDC is enforced twice: `auth::oidc` refuses an IP literal in a private range for the issuer and every endpoint of the discovery document and keeps such hosts off the allowlist (new failure code `oidc_blocked_target`), and the governed client refuses names that resolve to private addresses. Mail: where private addresses are not allowed, the host is resolved before each send, refused if one of its addresses is private, and the connection goes to the address that was checked with the certificate still verified against the host name (`Email::transport`) | a second setting for OIDC and mail; a pre-check only (DNS could answer differently for the connection) | `private_targets` in `apps/server/src/lib.rs` | DEC-534; security-audit.md SEC-4

LA-10 | "Categorised errors only for discovery and mail-test failures" (DEC-534) | "Send a test" answers `failed: <category>` (`not_configured`, `connection`, `auth`, `rejected`, `send_failed`, new `private_target`) instead of the transport's text; the text goes to the server log (warn). The page shows a sentence per category (`admin-mail-reason-*`, en and de). The provider Test already answered with a code only; the page now shows a sentence per code (`admin-sso-reason-*`) | keep the transport's text for admins of home instances | `send_test_mail` in `crates/api/src/admin/mail.rs` | DEC-534; UX4-22

LA-11 | Request read timeouts (deferral of DEC-653) | Three settings in seconds. `server.header_read_timeout_secs` (150): hyper's HTTP/1 header read timeout; `axum::serve` never ran it because it sets no timer, so the server has its own accept loop (`apps/server/src/serve.rs`, hyper-util, same graceful shutdown). hyper starts that timeout whenever it waits for a request head, so it is also the keep-alive idle time; the default is therefore above the time Caddy (2 minutes) and nginx (60 seconds) keep idle upstream connections by default, or the proxy could send a request into a closing connection. `server.body_idle_timeout_secs` (30): longest pause between two pieces of any request body. `server.body_read_timeout_secs` (60): a whole body, for every request except the import upload `POST /api/v1/imports` (64 MiB). A late body is answered `408` `request_timeout`. The limits run while something reads the body. With them, the pages router collects a body only for `/_fn/`; other paths get it unread behind a length limit (they read none), so a stalled body there pins nothing. HTTP/2 connections have no head timeout (a proxy speaks HTTP/1.1 to the application) | a head timeout of 30 s as the first draft had (below both proxies' defaults: sporadic resets on reused connections); `tower_http::timeout::RequestBodyTimeoutLayer` (idle limit only, a new direct dependency) | `axum::serve` back in `main.rs`; drop `read_timeout::layer` from `Server::guarded` | DEC-653; hyper 1.12 `server::conn::http1::Builder::header_read_timeout`; https://caddyserver.com/docs/caddyfile/directives/reverse_proxy and https://nginx.org/en/docs/http/ngx_http_upstream_module.html (read 2026-11-13)

LA-12 | Review SEC2-1: wrong one-time codes for one account spread over many addresses | A third count per account alone (key `t|<username>`), added on every wrong second factor (TOTP code or recovery code) at sign-in, the local sign-in, re-authentication and authenticator enrolment, with the pair's growing wait (`free_failures` free, then `delay_base_secs` doubling up to `delay_max_secs`, a quiet `window_minutes` starts it again); during the wait the code is not checked (`429`, `Retry-After`), a right code clears the count. It is checked only after the right password, so a stranger cannot make the owner wait at the second step (test "wrong passwords do not touch the code count"); someone who has the password can make the owner wait there, which is accepted (the password is known and has to be changed anyway). With the defaults this allows about 13 codes per 24 minutes (4 free, 9 growing waits, then a quiet window), about 800 a day, against 10^6 codes of which three are right at a time: more than a year on average. No notification to the admin after N such failures yet (out of scope, listed) | the review's suggestion to check the count in `Throttle::begin` whenever a code is sent (refuses before the password is checked; same bound, but a stranger who sends any code could then see that the account is waiting) | drop `code_begin`/`code_settle` in `Auth::second_factor` and `totp_confirm` | docs/reviews/2026-11-13-sec2-review.md SEC2-1; DEC-535

LA-13 | Review SEC2-5 and SEC2-6: size and eviction of the in-memory counters | A submitted name longer than `USERNAME_MAX_LEN` bytes cannot be an account; all such names share one placeholder in the pair key (`p|~too-long|<ip>`), so a key is never larger than about 100 bytes. `MemCounters` keeps each count with its own window and restart rule; at capacity it first drops keys whose own window is over, then pairs and code counts with the fewest failures (stalest first), address budgets last, so filling the map does not hand an exhausted budget back | hash the name into the key (same bound, needs a hash for no gain); refuse new pair keys at capacity (the owner's first failure at home would then not be counted) | `name_key` and `MemCounters::add` in `crates/auth/src/throttle.rs` | review SEC2-5, SEC2-6

LA-14 | Review SEC2-14: three small throttle points | (a) `free_failures` near `u32::MAX` no longer overflows (no wait at all then). (b) The pair wait is read before the verification and counted after it, so a burst of parallel guesses at one pair all pass the wait; they are still bounded by the address budget including attempts in flight (30 per window per address), and a burst of codes with the right password passes the account count of LA-12 at most as many at once as the verification cap lets through (8), because that count is read after the password verification. Accepted. (c) Provider test and discovery answer `oidc_blocked_target` apart from `oidc_unavailable`: a hosted admin learns that a name resolves to a private address. Kept on purpose: it is a category as DEC-534 asks, it tells the admin which setting to change, and no address, port or response text is shown | serialise checks per pair (a lock per key for a small gain); one code for both (the admin cannot tell a block from an outage) | `ThrottleSettings::delay`; `oidc.rs` error codes | review SEC2-14; DEC-534

LA-15 | Review SEC2-2: the head timeout was dodged by sending nothing or by speaking HTTP/2 | The listener serves HTTP/1 only, with hyper's `server::conn::http1::Builder` (header read timeout, timer, graceful shutdown as before) instead of hyper-util's auto builder: the auto builder reads up to 24 bytes to tell the protocols apart with no timer, and its `http1_only()` does nothing for `serve_connection_with_upgrades` (hyper-util 0.1.21 docs, seen in the red run). Protocol upgrades are not served (nothing in the workspace uses one). hyper's head timer starts when it waits for the first head, so a connection that sends nothing is closed after `server.header_read_timeout_secs`; an HTTP/2 preface is refused at once as a bad request line. A client that wants HTTP/2 gets it from the reverse proxy | keep HTTP/2 with a timeout around the first request and HTTP/2 keep-alive (more code for a protocol no documented setup uses between proxy and application) | `apps/server/src/serve.rs` back to `hyper_util::server::conn::auto` with `http2` features | review SEC2-2; LA-11

LA-16 | Review SEC2-7: the import upload had no total time | New setting `server.import_read_timeout_secs` (1800 s: 64 MiB at about 0.3 Mbit/s) for the whole body of `POST /api/v1/imports`; every other body keeps `body_read_timeout_secs`, all of them the idle limit. An upload without a session is refused before its body is read (the `Authed` extractor runs before the body; `it` test), so only a member can hold one open | a fixed multiple of `body_read_timeout_secs` (hidden coupling of two settings) | `ReadLimits::total_for` | review SEC2-7; DEC-653

LA-17 | Review SEC2-8: the private-address list | `domain::net::is_private_ip` also refuses 0.0.0.0/8, 192.0.0.0/24, 198.18.0.0/15, 240.0.0.0/4 (with the broadcast address), multicast (224.0.0.0/4, ff00::/8), site-local fec0::/10 and local-use NAT64 64:ff9b:1::/48; and the IPv4 address inside an IPv4-mapped, IPv4-compatible (::a.b.c.d), NAT64 (64:ff9b::/96) or 6to4 (2002::/16) address is classified like itself, so a public address in those forms stays public. Documentation ranges (192.0.2/24, 198.51.100/24, 203.0.113/24, 2001:db8::/32) and Teredo stay out: not routable, and the tests use them as public addresses | refuse every 6to4 and NAT64 address (also public ones behind them) | `private_v4`/`private_v6` | review SEC2-8; RFC 6890, RFC 6052, RFC 8215, RFC 3056

LA-18 | Review SEC2-3: one allowlist for every outgoing request | `outbound.allow_private_hosts` (types `domain::net::PrivateHosts` and `PrivateAllow`) is honoured by data sources (governed client, as before), sign-in providers (`auth::oidc` refuses an IP literal in a private range only when the host is not on the list; discovery, keys, token and user info), the mail server (checked per send) and notification channels (`check_target` and the plain client, which resolves names normally only for listed hosts). Entries are per host: `host` (the default port of the URL; for mail the ports 25, 465 and 587), `host:port`, an IP address in URL form, `*.domain`. Besides the list: connector base URLs count as listed for the governed client (LA-8) and the host of `[notify.smtp]` from file or environment for mail (the operator named it; a mail host an admin sets in the UI does not); `notify.allow_private_targets` (else the hosting mode) still allows providers and mail on any private address; notification channels get any private address only from `notify.allow_private_targets = true`, never from the hosting mode and never from the operator's other hosts. The wiring lives in `apps/server/src/outbound.rs` (`Outbound`). No upgrade note for an explicit `allow_private_targets = false` (greenfield rule until v1) | one predicate `Fn(host, port)` per feature without a shared type; list connector base URLs for every feature (a member could aim a webhook at the operator's mirror) | `Outbound::{oidc, mail, channels}` | review SEC2-3; DEC-534; LA-8, LA-9

LA-19 | Review SEC2-9: proxy variables of the environment | Every outgoing reqwest client (both clients of the governed client, both of the plain client) is built with `.no_proxy()`: through a proxy the target name is resolved by the proxy, out of reach of `PublicOnly`. An outbound proxy is not supported; the operations page says the server needs a direct way out. lettre does not read proxy variables | honour a proxy only when configured explicitly, with the statement that the proxy must do the filtering (no setup asks for it now) | the `.no_proxy()` calls in `catalog-core/src/{http,plain}.rs` | review SEC2-9

LA-20 | Review SEC2-10: mail where private addresses are checked | One transport per checked address, tried in order (`try_in_order`): a failure before the server answered (connection refused, timeout, TLS) moves on to the next address; an answer of the server (accepted, refused, transient) ends the round. All addresses passed the check, so no second lookup | prefer the address family the host can route (needs a probe of the host's routes) | `Email::deliver` | review SEC2-10

LA-21 | Review SEC2-11: host entries | Entries of `outbound.allow_private_hosts` are trimmed and lower-cased when the configuration is read; `*.domain` names every subdomain of `domain` (not `domain` itself); a bare leading dot and a `*` anywhere else are refused at start. The connector host lists use the same rules (`host_matches` now goes through `PrivateHosts`): the `.archive.org` suffix entry of LA-7 is replaced by `*.archive.org`, so the Open Library connector (lane v1-books, merged on main with `archive.org`) has to add `*.archive.org` when the two meet (docs/connectors/openlibrary.md says so) | keep the silent leading dot (LA-7) | `is_host` in `crates/config`, `PrivateHosts::covers` | review SEC2-11; supersedes the syntax of LA-7
