Date: 2026-11-06. Reviewer: a fresh session that did not produce any of the code. Scope:
`git diff 2edddfb` (commits 1835db8, 02a0444, 71399ec plus the uncommitted working tree)

## Summary verdict

Phase 0 is substantially done and done carefully. Every item of design.md section 9 "Phase 0"
is present: the tokens of 2.7 land in `src/web/style/input.css` exactly (zinc-500 field
borders, the four semantic colours with soft tints, `--destructive-text`, shadows, type scale,
`scroll-padding`, reduced motion with `!important`); the fourteen new `ui` components plus
`Disclosure`/`DisclosureGroup` (addendum D5-D7) exist with SSR tests, wasm keyboard tests,
gallery entries and axe checks; the icons are vendored from the pinned lucide-static 1.69.0
tarball and recorded in `icons.toml` and `config/brand/ICONS.adoc`; Atkinson Hyperlegible Next
is vendored with `OFL.txt`, the recorded SHA-256 sums match the files, and it is served from
the same origin under a content fingerprint with the route tested for a missing file and for
`..`; `ClientConfig` carries the session (resolved once per page by a middleware, DEC-186), so
the top bar is right on the first render and the owner's "Create account when signed in" bug
has an e2e assertion; `/history` and `/people` replace `/sessions` and `/companions` without
redirects (tested, the old paths render the 404 inside the signed-in shell); sign-up and
sign-in follow 5.2 with rules before typing, live normalisation shown rather than applied,
a throttled availability check that answers only when a sign-up is possible (DEC-184), three
free suggestions, one code per rule (DEC-185), an error summary that takes focus, and sign-in
that still does not say which part was wrong; every user-visible string is in Fluent with a
parity, key-usage and hard-coded-text check in `xtask/tests/locales.rs`, locale-aware numbers
and dates, Fluent plurals, per-user language with `<html lang>` and `lang` on foreign
fragments. The DECISIONS entries are specific and honest about what was cut (G chords, add
mode, closed-sign-up page, settings area).

Rules hold: ASCII only in everything added (the non-ASCII lines in the design docs are the
pre-existing German microcopy), no `kithkeep` outside `config/brand/` and `docs/`, no
`unsafe`, `anyhow` only in `apps/server`, no new lint allow-lists, no GPL material, no AI
attribution, no secrets. No high-severity defect found; no security defect in the new auth
code beyond the hardening note in UX0-9.

What falls short is accessibility polish of the shell and the test coverage the design
demands: the `Dialog` the shell now opens from the account menu neither traps nor returns
focus (UX0-1), the account menu loses focus on most of its own actions (UX0-2), and the
promised "axe on every page" is only on the auth pages and the gallery (UX0-3). Three 5.2 /
6.14 items are missing without a DECISIONS entry (UX0-4, UX0-5). The rest is low.
Recommendation: fix UX0-1 to UX0-5 before tagging `ux0`; the low findings can ride along or
go into phase 1.

## Findings

### UX0-1 (medium) Dialogs do not trap focus and do not return it to the opener

Evidence: `crates/ui/src/dialog.rs:31-36` focuses the panel when `open` turns true; there is
no `Tab` handling anywhere in the file and nothing records the previously focused element, so
closing (`dialog.rs:41,51,70`) leaves focus on `body`. Phase 0 wires two new openers to it:
the shortcut help from the account menu (`crates/web/src/shell.rs:474`, a menu item that is
unmounted as the dialog opens) and `?` (`shell.rs:245`), plus the existing palette
(`crates/web/src/palette.rs:132`). design.md 8 "Focus": "dialogs trap focus, label themselves
and return focus (APG dialog pattern)"; 7.1 lists "focus trap and return-to-opener verified"
for `Dialog`/`Sheet`. WCAG 2.4.3.

Recommendation: in `Panel`, remember `document.activeElement` on open and refocus it on close
(fall back to a caller-supplied `return_to: NodeRef` for openers that unmount, which the shell
passes as the account trigger); cycle `Tab`/`Shift+Tab` within the panel. Add a wasm test
(open, Tab from the last control lands on the first, Escape returns focus to the opener) and
an e2e step in `sharing.spec.ts` after "Keyboard shortcuts": close with Escape, expect the
account button focused.

### UX0-2 (medium) The account menu loses focus on theme, shortcuts and Tab; ArrowUp does not open it

Evidence: only `Escape` runs `close()` which refocuses the trigger (`shell.rs:412-421`). The
theme radios do `open.set(false)` only (`shell.rs:512-513`), the shortcuts item closes the
menu and opens the dialog (`shell.rs:474`), and `Tab` sets `open` to false while the focused
item is being unmounted (`shell.rs:423`), so focus falls to `body` in all three cases. The
trigger opens on `ArrowDown` only (`shell.rs:444`); the APG menu button pattern also opens on
`ArrowUp` (focus on the last item) and on `Enter`/`Space` it must focus the first item, which
works here only because of the effect at `shell.rs:401-406`. The e2e test checks Escape alone
(`src/web/tests/sharing.spec.ts`, "System" radio then Escape).

Recommendation: route every non-navigating item through `close()`; on `Tab` call `close()`
too (APG: focus moves to the next element after the button) or let the event through after
closing with the trigger focused; add `ArrowUp`. Extend the e2e test: choose "Dark" with
Enter, expect the trigger focused and `html.dark`; open with ArrowDown, expect the first item
focused.

### UX0-3 (medium) The axe check is not on every page, and the real shell is never checked

Evidence: `AxeBuilder` runs only in `src/web/tests/auth.spec.ts` (sign-up, sign-in) and
`gallery.spec.ts`; `i18n.spec.ts`, `notifications.spec.ts`, `sharing.spec.ts` and
`slice.spec.ts` have none. So no signed-in page with the top bar, account menu (open), bell,
You hub, mobile tab bar or the 404 page is checked, and nothing runs at a narrow viewport
where the tab bar is visible (`crates/ui/src/nav.rs:170-176`, `input.css` tab-bar height).
design.md 8: "the Playwright axe check already in M06 is extended to every page in the e2e
suite"; 3.2 "targets are at least 48 px" on the tab bar.

Recommendation: a shared `expectNoA11yViolations` helper (it exists twice already) and one
spec that signs in and visits `/`, `/library`, `/history`, `/people`, `/lists`, `/you`,
`/notifications`, `/integrations`, `/sources`, a 404 path and the open account menu, once at
1280x720 and once at 360x640 (assert the tab bar is visible there, its links >= 48 px tall,
and hidden at 1280). Run the same helper on `/invite/<bad-token>`.

### UX0-4 (medium) Lock-out does not show the remaining minutes; the throttle text is wrong for the availability check

Evidence: design.md 5.2: "lock-out shows the remaining minutes (`too_many_attempts`,
DEC-155)". The server has the number (`crates/auth/src/lib.rs:92-93`,
`retry_after_secs`), but `ErrorDto` carries only `code` and `message`
(`crates/contracts/src/lib.rs:204-208`), the message is the English developer string
(`crates/api/src/error.rs:77`, untranslated by DEC-199), and the client renders the code
alone: `crates/web/src/auth.rs:50` `form_message(i18n, code)` ->
`crates/web/locales/en.ftl:232` "Too many failed attempts. Please wait a few minutes." The
same key answers the username-availability throttle, where there were no failed attempts.
No DECISIONS entry records the deviation (DEC-189 lists eight choices; this is not one).

Recommendation: add `retry_after_secs: Option<u64>` to `ErrorDto` (serde default, so every
existing literal compiles) and a `Retry-After` header on 429; pass it through
`server::code` / `api::error_code` to a `too_many_attempts` message with a Fluent plural
(`{ $minutes -> [one] ... *[other] ... }`), and a second key for the availability check
("Too many checks right now; you can still create the account."). Unit test in
`web/src/auth.rs` and a REST test asserting the field.

### UX0-5 (low) 6.14 and 5.2 items missing from the auth pages without a DECISIONS entry

Evidence: design.md 6.14: "Centred 28 rem card, brand mark above, no app navigation, footer
with legal links from the brand." The card is there (`crates/web/src/auth_pages.rs:440`,
`:583`, `max-w-md` = 28 rem) but there is no brand mark above it and no footer; the brand
already has the data (`crates/brand/src/lib.rs:40-43`, `support_url`, `legal`, "shown in
the footer"), and the only footer in the app is the attribution one on the item page
(`crates/web/src/pages.rs:304`). design.md 5.2 last line: "Offline: the submit button is
disabled with 'You are offline' under it"; neither form reads the online state
(`auth_pages.rs:463`, `:601`), only the shell banner does (`shell.rs:652`). DEC-189 does not
mention either.

Recommendation: render the brand name as the mark above both cards (the logo slot can follow
with the attribution page), a `<footer>` with `brand.legal` links (add `legal` to
`ClientConfig`), and share the `online` signal from `OfflineBanner` through context so the
submit button gets `disabled` plus the "You are offline" line (`shell-offline` or a new key).
Playwright can assert both with `context.setOffline(true)`. If any of this is deferred on
purpose, record it in DECISIONS.

### UX0-6 (low) "Companions" still heads the People page; "Mark as done" next to "Completed"

Evidence: the route and navigation say People (`shell.rs:53-59`, `en.ftl` `nav-people`), but
the page renders `companions-title` = "Companions" as its H1 and list label
(`crates/web/src/sharing.rs:147,187`; `en.ftl:81`), and the notification body now says
"People page" (`crates/notify/locales/en.ftl`). The owner ruling renames the concept in the
UI (design.md 6.7 "People"). Also the owner chose the status word "Completed" over "Done"
(DEC-171) while the item page button stays "Mark as done" (`en.ftl:62`).

Recommendation: change `companions-title` to "People" / "Personen" (the list label can stay
"Companions" since that is the domain word, or use "People you know"), and "Mark as
completed" / "Als abgeschlossen markieren". Both are text-only changes; the e2e tests use
roles, not these strings.

### UX0-7 (low) Running text below the 0.8 rem floor

Evidence: design.md 2.8: "Body text never goes below 0.8 rem (12.8 px)"; the type scale
defines `text-small` (0.8) and `text-caption` (0.72, for badges and uppercase labels). The
live rule checklist, which is a sentence per rule, uses `text-xs` (0.75 rem,
`crates/ui/src/form.rs:232`); `KeyHint` keys use `text-[0.7rem]` (`crates/ui/src/copy.rs:124`).
Tab-bar labels at `text-xs` (`crates/ui/src/nav.rs:142`) are captions and fine.

Recommendation: `text-small` for the checklist and `text-caption` (or `text-xs`) for the
key caps; both exist as utilities from `input.css`.

### UX0-8 (low) Script-data escaping of the hydration config covers `</` only

Evidence: `crates/web/src/app.rs:103` serialises `ClientConfig` into
`<script type="application/json">` and escapes only `</`. `display_name` is user text; the
sequence `<!--` followed by `<script` puts the HTML tokenizer into the script-data
double-escaped state, where the real closing tag is consumed and the rest of the head is
parsed as script data. It is self-inflicted (the name is the viewer's own), so a broken page
for that account only, but the rule is cheap.

Recommendation: escape `<` as `\u003c` in that one place (the JSON stays valid; U+2028 and U+2029
are not a concern inside a script data block); a unit test with a display name of
`<!--<script>` asserting the output has no `<`.

### UX0-9 (low) Sign-up runs argon2 before the username uniqueness check; the window is consumed before the gate

Evidence: `crates/auth/src/lib.rs:354-357` hashes the password, then looks the name up and
answers `username_taken`. A taken-name probe through `POST /auth/sign-up` (unthrottled,
DEC-184 says so) therefore costs the server an argon2 run per request while revealing exactly
what the throttled endpoint reveals. In `username_available` the per-instance window slot is
taken (`lib.rs:428`) before `signup_gate` (`lib.rs:429`), so a closed instance burns its
30/min budget on calls that do no lookup.

Recommendation: move the `user_by_username` check in front of `hash_password` (the
`Conflict -> UsernameTaken` mapping at `lib.rs:371-374` still covers the race), and take the
window slot after the gate. Existing tests cover the behaviour; add one that a closed
instance does not count towards the limit if the order is changed.

### UX0-10 (low) Every page request loads a full inbox page to count unread

Evidence: `apps/server/src/web_backend.rs:84-86` calls `notifications::inbox`, which fetches
`INBOX_LIMIT` items and maps them to DTOs (`crates/api/src/notifications.rs:86-96`), then
counts `!read`. This runs in the middleware on every page GET of a signed-in user
(`crates/web/src/backend.rs:resolve_shell_session`). DEC-186 records the cap, not the cost.

Recommendation: a `count_unread(user)` on `NotifyStore` (`SELECT count(*) ... WHERE read_at
IS NULL`) and use it here; keep the cap if the number is also shown.

### UX0-11 (low) The account menu re-parses the Fluent catalogues on every open; no username

Evidence: `language_options()` (`shell.rs:530-538`) builds `I18n::new(l, ...)` for every
locale to read `locale-name`; each `I18n::new` parses the locale's `.ftl` plus the English
fallback (`crates/web/src/i18n.rs:bundle`), and `LanguageItems` sits inside
`<Show when=open>` (`shell.rs:455-465`), so four catalogue parses happen in the browser per
menu open. It also ignores brand string overrides for the name. Separately, 3.2 asks the menu
head for "display name and username"; only the display name is shown (`shell.rs:455`) and
`ClientConfig` has no username.

Recommendation: read `locale-name` once (a static table in `contracts::locale`, or compute
the options once in `AppShell` and provide them by context); add `username` to
`ClientConfig`/`ShellSession` and show it under the name.

### UX0-12 (low) Behaviours without a test

Evidence (test-driven rule 4; each exists in code, none has an assertion):

- Unread count > 0: the bell dot, "Notifications, N unread" and the You count
  (`shell.rs:338, 631, 721`); `apps/server/tests/shell.rs:113` asserts only that
  `"unread":` is in the config.
- Offline banner (`shell.rs:652-671`): no e2e with `context.setOffline(true)`.
- `?` and `N` shortcuts and their suppression in text fields (`shell.rs:236-262`); the
  account-menu arrow keys and Home/End (`shell.rs:150-184`).
- A request with a bogus or expired session cookie renders the signed-out shell
  (`backend.rs:resolve_shell_session`).
- The Show toggle on the real sign-up page (`auth_pages.rs:98-125`) is only tested in the
  gallery; the `aria-pressed` flip and `aria-controls` are not.
- `section_of` for `/you` subpages and `aria-current` on the desktop links is unit-tested,
  but no e2e asserts `aria-current="page"` on the current section.

Recommendation: one e2e spec for the shell (unread via a seeded notification, offline, keys,
aria-current, mobile viewport) and a server test with `cookie: app_session=bogus`.

### UX0-13 (low) Bottom padding for the tab bar is applied when there is no tab bar

Evidence: `src/web/style/input.css` sets `--tab-bar-height: 4.5rem` below 47.5 rem for every
page; `<main>` pads by it (`shell.rs:280`) and the toaster is lifted by it
(`crates/ui/src/toast.rs:85`), but the tab bar renders only when signed in (`shell.rs:283`).
Signed-out mobile pages (sign-in, sign-up, shared lists) get 72 px of dead space and a
floating toaster.

Recommendation: set the variable from a class the shell adds when `signed_in` (for example
`.has-tab-bar { --tab-bar-height: 4.5rem }` inside the media query) or inline-style it on
`<main>`; keep `scroll-padding-bottom` on `html` in sync.

## Test quality

Strong where the behaviour is a function: every `ui` component has an SSR render test with
ARIA assertions and the keyboard ones have wasm tests; the form logic is unit-tested in both
locales; the auth rules, gate and throttle have integration tests; the shell and language
have server-rendered tests; the e2e suite covers the owner's two complaints (top bar after
sign-in, form discipline) with axe on the auth pages. Weak where the behaviour is in the
browser shell: no axe on signed-in pages, no mobile viewport, no unread, offline or shortcut
assertions (UX0-3, UX0-12), and the `Dialog` focus contract is asserted nowhere (UX0-1).

DECISIONS if deferred on purpose). UX0-6 to UX0-13 are small; apply them in this phase or
carry them into phase 1 with a DECISIONS line each.

## Disposition (applied 2026-11-06)

Every finding is applied; none is rejected. Choices the review left open are recorded in
DEC-203. Tests named below were written first and seen failing before the fix.

- **UX0-1 applied.** `ui::Dialog`/`Sheet` follow the APG dialog pattern: the opener is
  remembered on open and refocused on close, with `return_to` (an element id) as fallback when
  the opener is gone; Tab/Shift+Tab wrap inside the panel; Escape closes. The shortcut help
  passes the account button as `return_to`. Tests: `crates/ui/tests/wasm.rs`
  `dialog_traps_focus_and_returns_it_to_the_opener`,
  `dialog_returns_focus_to_the_fallback_when_the_opener_is_gone`; e2e `shell.spec.ts`
  (shortcut help from the menu: Tab stays inside, Escape returns to the account button; the

- **UX0-2 applied.** Every item that stays on the page closes through `close()` (theme,
  language, shortcuts, help link), Tab closes with focus on the button so Tab moves on from
  there, ArrowUp opens on the last item. Test: e2e `shell.spec.ts` "the account menu follows
  the APG menu button pattern" (ArrowDown/ArrowUp/Home/End/wrap, Dark with Enter returns focus
  and sets `html.dark`, Tab lands where Tab from the button lands).
- **UX0-3 applied.** Shared `src/web/tests/helpers.ts` (`expectNoA11yViolations`, also used by
  `auth.spec.ts` and `gallery.spec.ts`); `shell.spec.ts` runs axe signed in on `/`, `/library`,
